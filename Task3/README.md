## Требования к безопасности

### Управление данными и конфиденциальность

- Партнерские API должны запрашивать/принимать только данные, абсолютно необходимые для выполнения конкретной операции.

- Биометрические шаблоны (лица) и списки номеров автомобилей передаются из системы PropDevelopment и должны также храниться в партнерской системе. При запросе пользователя PropDevelopment передает только событие ("открыть для пользователя X") или одноразовый токен.

 - Все логи на стороне партнера, содержащие ПДн или персональные идентификаторы, должны маскироваться

 - Должен быть определен и согласован срок хранения различных категорий данных (сырое видео, биометрические шаблоны, логи событий) и механизмы их безопасного удаления.

### Безопасность API и инфраструктуры

 - Все API-эндпоинты партнера, доступные извне, должны работать исключительно по протоколу TLS 1.2+ с корректно настроенными сертификатами от доверенного УЦ. В дополнении также настроено ограничение от доверительных IP адресов.

 - Должна быть обеспечена защита от распространенных веб-атак: инъекции (SQL, Command), XSS, CSRF, неправильная десериализация.

 - Обязательное применение ограничения частоты запросов (Rate Limiting) на все публичные API для предотвращения атак на отказ в обслуживании (DoS) и подбора данных.

 - Доступ к административным функциям партнерской системы (настройка правил, доступ к БД) должен быть изолирован от API, используемых PropDevelopment, и недоступен из публичной сети.


Аутентификация  в интеграции данных между системами обеспечивается через OAuth 2.0 Client Credentials Grant

Аутентификация и авторизация пользователя обеспечивается через OAuth 2.0 OpenConnectId. Используя JWT токен

Взаимодействие между предприятием и партнерской системой производится через REST API HTTPS
